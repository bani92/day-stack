# DayStack 제품 기획서

## 1. 제품 정의

DayStack은 Todo 서비스가 아니라, 1인 개발자와 학습자가 매일의 실행·학습·막힘·다음 행동을 기록해 성장의 흐름을 쌓아가는 Daily Log 서비스다.

핵심 문장은 다음과 같다.

> 오늘을 네 가지 질문으로 남기고, 시간이 지난 뒤 다시 읽는다.

## 2. 해결하려는 문제

- 개발과 학습은 과정이 길어 오늘 무엇을 했는지 쉽게 잊는다.
- 작은 학습과 해결 과정이 흩어져 성장의 흐름이 보이지 않는다.
- Todo 목록은 남지만 왜 했고 무엇을 배웠는지는 남기 어렵다.

## 3. 제품 원칙

1. 기록은 1~2분 안에 끝난다.
2. 모든 질문에 답하지 않아도 기록할 수 있다.
3. 통계는 압박이나 평가가 아니라 축적을 보여준다.
4. 첫 방문부터 가입 없이 오늘 기록을 시작한다.
5. 날짜당 Daily Log는 하나만 둔다.

## 4. MVP 범위

### 포함

- 오늘 날짜의 Daily Log 작성 및 수정
- 날짜 선택, 이전/다음 날짜 이동
- 날짜별 기록 읽기
- 네 필드 전체 대상 부분 문자열 검색
- 검색 결과에서 해당 날짜로 이동
- 현재 연속 기록일, 최장 연속 기록일, 월간 기록일 수
- 브라우저 `localStorage` 저장
- 데스크톱·모바일 반응형
- 데이터 JSON 내보내기·가져오기

### Daily Log 필드

| 필드 | 의미 | 저장 정책 |
|---|---|---|
| `done` | 오늘 한 일 | 선택 입력 |
| `learned` | 오늘 배운 점 | 선택 입력 |
| `blocked` | 막힌 점 | 선택 입력 |
| `next` | 다음에 이어갈 일 | 선택 입력 |

네 필드가 모두 비어 있으면 저장하지 않는다. 하나 이상 내용이 있으면 부분 기록으로 저장한다.

### 제외

회원가입, Supabase Auth, 서버 저장, 다중 기기 동기화, 공유·협업, Todo 상태/마감일, 프로젝트·태그, 첨부파일, AI, 알림, 소셜 기능, 복잡한 생산성 점수는 MVP에서 제외한다.

## 5. 핵심 사용자 흐름

### 첫 방문

1. `/`에서 `/today`로 이동한다.
2. 오늘 날짜의 빈 기록 화면을 보여준다.
3. 네 가지 질문에 답한다.
4. `기록 저장`을 누른다.
5. 저장 상태와 현재 연속 기록을 확인한다.

### 과거 기록

1. 날짜 선택기 또는 이전/다음 버튼을 사용한다.
2. 해당 날짜 기록을 읽는다.
3. `수정`으로 입력 모드에 들어간다.
4. 저장 후 `updatedAt`을 갱신한다.

### 검색

1. `찾기` 화면에서 검색어를 입력한다.
2. `done`, `learned`, `blocked`, `next` 전체를 대소문자 구분 없이 검색한다.
3. 결과에 날짜·프롬프트명·한두 줄 발췌를 표시한다.
4. 결과를 선택하면 해당 날짜 기록으로 이동한다.

### 돌아보기

1. `돌아보기` 화면에서 현재 연속 기록, 최장 연속 기록, 월간 기록일 수를 본다.
2. 기록된 날짜를 확인한다.
3. 날짜를 선택하면 해당 기록으로 이동한다.

## 6. 통계 정책

- 오늘 기록이 있으면 오늘부터 연속 기록을 역산한다.
- 오늘 기록이 없으면 어제까지 이어진 기록을 현재 연속 기록으로 계산한다.
- 하루가 비면 연속 기록이 끊긴다.
- 월간 기록일 수는 해당 월에 저장된 로그 날짜의 개수다.
- 기록이 없는 날은 실패 상태로 표시하지 않는다.

## 7. 데이터 계약

```ts
export type DailyLog = {
  date: string; // YYYY-MM-DD, 사용자 로컬 날짜
  done: string;
  learned: string;
  blocked: string;
  next: string;
  createdAt: string; // ISO timestamp
  updatedAt: string; // ISO timestamp
};

export type DayStackSnapshotV1 = {
  version: 1;
  logs: Record<string, DailyLog>;
};
```

저장 키는 `daystack:data`로 고정한다. JSON 파싱 실패나 잘못된 버전은 기존 값을 덮어쓰지 않고 저장 오류 상태로 보여준다. 날짜 계산은 UTC 변환이 아닌 브라우저의 로컬 달력 기준으로 처리한다.

## 8. 성공 기준

### 기능

- 첫 방문 후 오늘 기록을 바로 저장할 수 있다.
- 새로고침 후 기록이 유지된다.
- 과거 날짜 기록을 읽고 수정할 수 있다.
- 검색 결과에서 날짜로 이동할 수 있다.
- 연속 기록과 월간 기록일 수가 실제 기록과 일치한다.
- 빈 상태·검색 결과 없음·저장 실패를 안내한다.
- JSON 백업과 복원이 동작한다.

### 제품 검증

초기 사용자 10명을 대상으로 첫 기록 2분 이내 완료율 80% 이상, 7일 동안 3일 이상 기록하는 사용자 40% 이상을 목표로 한다. 가장 중요한 검증 질문은 다음이다.

> 사용자가 기록 후 며칠 뒤 다시 과거 기록을 읽고 다음 행동을 이어가는가?

## 9. Supabase 전환 기준

다음 조건을 모두 충족하면 2단계로 전환한다.

- 10명 이상이 7일간 사용한다.
- 그중 5명 이상이 3일 이상 기록한다.
- 3명 이상이 계정, 다중 기기 또는 데이터 복구를 요구한다.

2단계에서는 `@supabase/supabase-js`, Auth, 사용자별 `daily_logs` 테이블, RLS, 명시적 로컬 데이터 가져오기를 추가한다. `DailyLog`와 Pinia Store의 외부 계약은 유지하고 Repository 구현체만 교체한다.
